# 背包与历史技能兼容审计（2026-10-12）

当前基线为已发布 2.1.07-r1（77280fd4efb197add52dbf84bfbdced1f1743d0b），开发工作树 HEAD 与暂存区保持原样。本轮仅做源码和生产 C 夹具验证。

历史修复核对：

- 7139a03、129c389：模块与进程绑定、映射导入修复、loader/apphelp 恢复、回调退出与资源管理。当前传输层已有，外机记录已进入 UnitAddAbility 业务调用。这些修复不解释正常 false 返回。
- da28c4e、2b90f22：特定 SetUnitAbilityLevel 尾部异常，严格核对异常位置/指令和目标等级。当前共用添加/激活与施法路径已有；它不把 UnitAddAbility 的正常拒绝改为成功。
- 1134c97、0f4d9fc、b91bf4e：由引擎创建真实实例，begin/add/end/refresh 顺序，完整单位身份，严格清理。旧内部地址及解析规则属于 2.0.4；当前 3.0 调用已确认的原生 handler，不搬旧地址/对象资源指针，不复制运行时载荷。
- 1a64ab7、54146cc、50a081b：绑定对象的能力列表查找、注册状态重置后保留对象绑定、操作前后实例验证。当前单位添加已使用直接查询+有界枚举；当前物品能力挂载却未在直接查询空时消费已经读到的同物品列表。
- e1c9dca：全屏季风/群星等的点/立即/范围/持续效果路由，已被当前统一 held effect 路径保留。本轮未改变全屏施法。

确定遗漏与本轮修复：

1. 物品能力已在列表中，直接查询却返回空时，旧代码仍调用 BlzItemAddAbility，可能重复挂载，并在后置直接查询空时误报失败。现在复用共用枚举匹配规则，从同一完整身份的物品列表取唯一实例。
2. 新能力挂载后，直接查询空但同物品列表已出现唯一实例，使用列表读回验收；false 返回也只在读回成立时接受，添加始终最多调用一次。
3. 同能力编号多实例、列表重复句柄、直接查询与列表指向不同对象时停止。原有物品、能力、槽位、数量和单位/物品完整代际检查保留。
4. 日志增加挂载前后 direct/indexed 查询依据，错误 443/444 通过统一中英文解释器；item_ability 协议更新至 0x24268070，尺寸保持 58632，Python/C/验证器同步。

验证：production-before-after.json 使用上一发布的物品生产 C 源码和修复后的源码，加载相同故障注入函数、同一四版本 profile，比对重复添加、反射查询空与歧义对象；这是离线代码复现，不是问题外机游戏复现。其余结果见 static-gates.json 与 preserved-compatibility.json。

外机故障边界：旧日志准确证明修改器 2.1.06 / 游戏 3.0.0.24268 给 O605 添加 AIni 返回 false，错误 25 是修改器业务分类。它未记录当时单位/物品能力实例列表。因此不能将本轮确定代码遗漏直接认定为外机唯一内部根因；外机面板恢复未验收。本轮不操作本机游戏，不以继续索取外机日志为前置条件。
