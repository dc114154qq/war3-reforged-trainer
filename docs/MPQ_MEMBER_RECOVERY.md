# 补齐定义：缺失归档文件名的处理

## 已确认的故障

2026-10-23 的《真阿克恩特别爽版 1.04》原文件 SHA256：

`44f7836bdd6aeb1cad38edb067e165ed2bb2bd8e0f9058cbf345d64bf8bd3c30`

战役含 86 章。第一章 `Chapter05.w3x` 的 MPQ 哈希表只有 16 个槽位，
内部 `(listfile)` 又缺少真实文件名。StormLib 在扩大目录时返回
`10007 / ERROR_UNKNOWN_FILE_NAMES`。仅把容量写成更大的数字，不能完成重新散列。
单独请求原容量时还出现了 112；这不是磁盘空间不足的证据。

目录清单缺失不会直接说明地图内容丢失：游戏按已知路径计算哈希，仍能找到文件。
这类地图需要先恢复工具的文件名缓存，再添加背包对象表。

## 实现

1. 打开归档时，探测标准地图成员、地形、界面、光标与载入画面路径。
2. 对仍未识别的文件，从原地图脚本、对象和模型字符串中提取有界的路径候选。
   支持 UTF-8、JASS 的双反斜杠、`.mdl` 对应 `.mdx`、模型的 `_Portrait.mdx`
   以及 `BTN` 对应 `DISBTN`。
3. 先读取已知文件，再按新识别的路径读取模型，避免以假文件名解密小型加密文件。
   扫描最多 8 轮、每个成员 32 MiB、累计 128 MiB、候选 10000 条；支持取消。
4. 通过 `SFileOpenFileEx` 确认实际哈希匹配，立即关闭文件句柄。
   候选只用于内存中的文件名识别，不创建候选文件、不重命名资源。
5. 目录容量按实际成员数、新增成员数与余量计算，再由 StormLib 正常扩容。
   立即保存 Win32 原始错误码，并读回扩容后的容量。
6. 一些编辑器留下多份 `(listfile)` / `(attributes)`。仅这两种由库维护的元数据
   允许合并枚举结果并记录原块号；实际地图内容的重名冲突继续报错。
7. 写入临时副本后重新打开、解压并比较所有实际原成员的 SHA256、locale 和存储标志，
   同时核对所有新增对象表。全部通过才输出，原文件保持原样。

确实仍缺少文件名时停止处理，并显示实际章节和错误码、保留详细 JSONL。
不通过丢弃未知成员、按猜测改名或重新打包来绕过完整性检查。

## 固定标准路径的来源

`war3_mpq_names.py` 内含 1191 条固定路径，仅作为哈希探测候选。
程序运行时不依赖本机游戏目录或联网下载。这些名称来源于本机已提取的
官方地形表、界面表与 CASC 命名空间，SHA256 如下：

| 来源 | SHA256 |
| --- | --- |
| `Terrain.slk` | `12919abf88a6016659cbd870fa8cd9b8a1ea0626a73f2015786721009da06d07` |
| `CliffTypes.slk` | `0b4d3870494f317f9f0a04533e4f2f9b87b580a6394ef0458f98584d723202bb` |
| `UI/war3skins.txt` | `f3c613ae88fc02ab607ff3b07af937e2570c0656e4b184bdd1a186255bb60956` |
| CASC 文件路径清单 | `27a4fa17c981f14934ffd41f7f820128b72b5d9e33991d5aada3aa13db4e3f7d` |

标准地图文件与四种族光标的少量固定路径另列于 `WARCRAFT_MEMBER_NAMES`。

## 验证边界

回归测试使用真实 StormLib 创建无 listfile 的小容量 MPQ，先复现 10007，
再走正式处理入口，核对加密资源、模型配套文件和新增定义。
对未引用的私有未知文件，验证保留原件且不输出半成品。

归档和对象表验证与实际进入游戏是两项不同证据。处理报告的
`gameplay_tested` 保持 `false`，不会把离线验证描述成所有章节已玩过。
