# 补齐定义：缺失归档文件名的处理

## 已确认的故障

2026-10-23 的《真阿克恩特别爽版 1.04》原文件 SHA256：

`44f7836bdd6aeb1cad38edb067e165ed2bb2bd8e0f9058cbf345d64bf8bd3c30`

战役含 86 章。第一章 `Chapter05.w3x` 的 MPQ 哈希表只有 16 个槽位，
内部 `(listfile)` 又缺少真实文件名。StormLib 在扩大目录时返回
`10007 / ERROR_UNKNOWN_FILE_NAMES`。仅把容量写成更大的数字，不能完成重新散列。
单独请求原容量时还出现了 112；这不是磁盘空间不足的证据。

目录清单缺失不会直接说明地图内容丢失：游戏按已知路径计算哈希，仍能找到文件。
这类地图需要先恢复工具的文件名缓存，再添加背包对象表。

## 实现

1. 打开归档时，探测标准地图成员、地形、界面、光标与载入画面路径。
2. 对仍未识别的文件，从原地图脚本、对象和模型字符串中提取有界的路径候选。
   支持 UTF-8、JASS 的双反斜杠、`.mdl` 对应 `.mdx`、模型的 `_Portrait.mdx`
   以及 `BTN` 对应 `DISBTN`。
3. 先读取已知文件，再按新识别的路径读取模型，避免以假文件名解密小型加密文件。
   扫描最多 8 轮、每个成员 32 MiB、累计 128 MiB、候选 10000 条；支持取消。
4. 通过 `SFileOpenFileEx` 确认实际哈希匹配，立即关闭文件句柄。
   候选只用于内存中的文件名识别，不创建候选文件、不重命名资源。
5. 目录容量按实际成员数、新增成员数与余量计算，再由 StormLib 正常扩容。
   立即保存 Win32 原始错误码，并读回扩容后的容量。
6. 一些编辑器留下多份 `(listfile)` / `(attributes)`。仅这两种由库维护的元数据
   允许合并枚举结果并记录原块号；实际地图内容的重名冲突继续报错。
7. 写入临时副本后重新打开、解压并比较所有实际原成员的 SHA256、locale 和存储标志，
   同时核对所有新增对象表。全部通过才输出，原文件保持原样。

对常规目录，继续由 StormLib 正常扩容。2026-10-28 起，对经典 V1 归档仍缺少
文件名的情况，提供下述保持原查找链和资源存储的扩容，不丢弃未知成员，
不把枚举占位名当作真实资源名，不重新打包原资源。格式或完整性证明不满足时仍停止。

## 2026-10-28：异常头部与无名资源

用户的《平行世界：圣光之子阿尔萨斯》v1.5 中，`8.w3x` 头部偏移为 512，
经典 V1 的头部长度却为 356846300（应为 32）。StormLib 能读但拒绝改写，
扩容返回 5。只在测试副本纠正该字段后，错误转为 10007；剩余模型实际位于
`war3mapImported`，旧文件名提示没有覆盖默认导入前缀。其他章节另有无引用资源。

1. 路径识别增加标准默认导入前缀和有效 MDX MODL 内部名称提示；最终仍须通过
   实际 MPQ 哈希匹配，不根据提示创建、重命名或替换原资源。
2. 仅在服务拥有的临时副本中，检查经典 V1 头部、表范围、格式和目录容量。
   对长度字段异常但其余结构一致的情况，先读完所有原成员，只改长度的四字节，
   再重新打开逐成员比较名称/locale/块号/大小/flags/内容哈希；失败或取消恢复原字节。
   正常头部不改、不增加逐资源扫描；其他格式不套用 V1 的修复。
3. 原生扩容返回 10007 时，用独立候选复制原哈希探测数组到更大的 2 次幂目录。
   未知条目保持原哈希、locale、platform 和块号；已知条目在各副本中变为墓碑，
   再按已验证全名的完整哈希插入一次。原来的空槽和删除槽语义保留。
4. 证明：旧数组长度 N，新长度 r*N。任意未知文件从新哈希起点开始，先看到的
   N 个槽与旧数组从原起点开始的序列一致；其原条目仍在链中，已知项只变成墓碑
   或新占用项，没有引入更早的空槽，所以原有文件的成功查找不会丢失。
   新增已知文件继续使用标准的完整哈希查找。
   不能仅把现有无名条目搬到猜测的新位置。
5. 未知哈希条目按需要保留多份；枚举仅合并原哈希记录和块身份完全相同的冗余项。
   同名不同块、不同哈希或有歧义的实际内容仍保持原严格冲突规则。
6. 新目录附加在归档尾部。原块表、资源字节及绝对存储位置不动，FIX_KEY 加密键
   因而不因移动改变。除归档大小/哈希表偏移/哈希表容量三个字段外，候选的全部
   原文件前缀字节必须与输入匹配；StormLib 还需重新验证全部逻辑成员身份和容量。
   候选校验通过才替换服务临时文件，出错/取消保留或恢复旧副本并重新打开句柄。
7. 无名资源或冗余哈希项存在时，不进行会移动资源的自动归档整理，明确记录跳过。
   同设置的重复注入仍沿用原有字节不变机制，不叠加新脚本。
8. 该路线仅支持边界有效的经典 V1：目录最多 262144 槽、最多 64 倍复制、
   最多 4000000 次插入探测，且新增目录不能超出 V1 的 32 位归档范围。
   所有生成过程有取消检查。无法完整读取/校验的原成员继续拒绝输出。

日志记录 `classic-header-preserved-hash-v1-20261028` 写入修订，包含原/新头字段、
校验成员数量、原生拒绝码、复制倍数、已知/未知槽数、实际新容量、原字节验证、
逻辑身份验证、回滚和归档整理跳过原因。原生 10007 会保留为诊断事件，但后续验证
成功后不作为整个任务失败。

## 固定标准路径的来源

`war3_mpq_names.py` 内含 1191 条固定路径，仅作为哈希探测候选。
程序运行时不依赖本机游戏目录或联网下载。这些名称来源于本机已提取的
官方地形表、界面表与 CASC 命名空间，SHA256 如下：

标准地图文件与四种族光标的少量固定路径另列于 `WARCRAFT_MEMBER_NAMES`。

## 验证边界

回归测试使用真实 StormLib 创建无 listfile 的小容量 MPQ，先复现 10007，
再走正式处理入口，核对加密资源、模型配套文件和新增定义。
对未引用的私有未知文件，验证扩容后仍能用真实原文件名读取、加密/存储标志不变；
碰撞链、首尾环绕查找、已知脚本替换、多次扩容、候选校验失败、取消及异常头回滚
均有实际 StormLib 回归。结构边界不一致的输入仍拒绝且不输出半成品。

归档和对象表验证与实际进入游戏是两项不同证据。处理报告的
`gameplay_tested` 保持 `false`，不会把离线验证描述成所有章节已玩过。
