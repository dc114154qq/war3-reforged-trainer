# 24268 当前适配检查（2026-09-13）

目标仍为完整、快速、稳定、跨设备的 3.0 修改器；下面只记录本轮证据，不代表整体目标完成。

## 本轮修正

- 玩家资源从 owner+0xA0 的属性数组读取。owner+0xA8 是容量字节数，+0xC8 是有效元素数；当前 28 个玩家均为容量 32、有效 26。旧代码访问容量尾部，实际在玩家 26 遇到无效地址。
- 属性 +0x7C 为状态编号：金币 1、木材 2、人口上限 4、已用人口 5、人口限制 6；值位于 +0xD0，金币/木材按 10 倍存储。旧映射把金币、木材及人口上限错位。
- 列表、逐行刷新、本地玩家定位、身份校验及资源写入现在使用同一条路径。缓存绑定 PID、玩家完整句柄、owner 及属性地址；失效时报告原因。完整请求先校验，列表出错不返回偷偷减少的玩家行。
- 单位 owner+0xD8 指向真实的附属对象链表，节点为 wrapper+0x38；节点 +0 为前驱、+8 为后继，首节点前驱为 owner+0xD0，尾部为零。wrapper+0x50 回指 owner，+0x90 为对象数据。此链也包含 task 记录，不能把所有节点都当成技能。
- 组件读取改为两次一致的链表遍历和注册表身份校验，移除当前 3.0 路径中 owner+0x158 分配距离猜测、旧组件偏移及区域扫描。技能实例也从该链取得；技能创建和复制尚待引擎执行适配。
- 背包 wrapper 类为 AInv，但数据 rawcode 可为 Aihn 等。3.0 直接使用已验证组件数据，不再每隔 0x210 搜寻附近对象。
- 英雄智力读取不再探测旧版本内部函数。当前缓存候选值与引擎属性接口的最终语义仍须专项验证。
- 删除当前分支的 war3_native_helper.dll 和 war3_native_helper.3.0-live.dll，并移除 3.0 spec 对旧实现的打包引用。运行时也不再搜索这些文件。旧 C 协议、参考测试和未迁移功能代码尚有残留，未宣称已全部清理；新的 24268 引擎执行模块尚未交付。
- 移除多客户端按新旧/读取成功/选中数量排名的自动绑定。仅一个客户端时自动连接；多个客户端时需要明确 PID，GUI PID 输入框可编辑。当前绑定刷新不自动改绑其他客户端。
- 通用 GUI 操作异常保存到 EXE 旁 log/trainer-error-时间-pid*.log 和 trainer-error-latest.log；目录不可写时使用临时目录 War3ReforgedTrainer/log。包含操作名、版本、PID、路径、完整 traceback，弹窗附日志位置。

## 验证

可复现脚本：`verify-24268-indexed-public.py PID --write-roundtrip --output REPORT.json`。必须指定 PID；默认仅只读，显式参数才临时将本地金币/木材各加 1 并恢复。

`24268-indexed-public-live.json`：PID 32868，28 个资源组、15 个选中单位、英雄 77 个字段。资源列表 46.5 ms，选中字段读取 39.0 ms，金币/木材写入 11.9 ms，原值恢复成功。测试将 helper 调用和 ProcessMemory.regions 替换为直接报错，确认这些公开接口未使用它们。

资源和组件故障测试覆盖错位值、容量尾部无效指针、缺项、重复、跨进程缓存、句柄/地址变化、循环链、错误 owner、读取期间变链及组件移除。日志、多客户端和旧 DLL 搜索另有回归测试。

完整回归：1725 passed，169 subtests passed（177.03 s）。随后新增产品边界测试与相关用例：20 passed，11 subtests passed（2.56 s）。
