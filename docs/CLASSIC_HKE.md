# 经典版火龙脚本来源与接入范围

本地实现基于下载取得的 HkeW3mModifier 2.06 所附 **HKE 1.25B** 脚本，原作者为火龙 / WuHansen。2.06 是桌面工具版本，1.25B 是它附带的地图脚本版本。下载镜像并非作者的当前维护站，不将镜像的上传日期视为脚本更新时间。

来源：<https://github.com/j8383888/War3Tool/tree/master/HkeW3mModifier2.06>。固定 Git blob 与 SHA256 见 `tools/prepare_huolong_classic.py` 和 `war3_huolong_data.py`；只将 g.j/f.j/m.j 文本加入构建，旧 EXE 不运行、不随新 EXE 打包。原始作者署名与菜单中的作者信息保留，不将原版脚本宣称为本项目原创。

静态清点原版为196个函数、146处菜单按钮创建、17处对话框事件注册、4处方向键注册。保留原版帮助、命令、方向键、参数默认值及正常动作函数，通过短名称前缀隔离地图符号。主菜单增加翻页和下述功能，复用原主菜单对话框及点击事件，没有单独的增强主菜单。

## 主菜单扩展

- 原版主菜单项目与新增项目一起分页，每页最多6个功能。目录页每页4个对象，另有搜索与筛选；包含导航在内最多10个按钮。长说明分段查看。
- 物品、技能、单位召唤、科技目录采用本章节的原生和自定义数据，解析战役共用、章节和skin覆盖、名称、效果和继承等级。支持代码快速检索、名称检索、地图改动筛选、收藏与最近使用。
- 六神器方案在桌面注入页配置并持久保存，随脚本写入地图；游戏内领取不连接修改器。普通物品栏满时不创建，不移除原物品；可以明确选择生成到地面。拾取即生效的物品只提供地面生成。
- 物品操作先选择具体槽位，继续核对相同单位、槽位和物品；可复制、丢下和设置充能，非充能装备不会被改成消耗品。原生添加未确认时保留创建物品，不删除或重放。
- 技能逐项添加/删除/调级并读回；常用光环/被动按当前章节最高有效等级处理，某项被拒绝继续其他项目。英雄和普通单位共用此流程，背包控制能力被排除。
- 新增批量恢复、清冷却、无敌、暂停/恢复、移动速度/朝向/缩放；英雄等级/经验/剩余技能点/基础三围/玩家经验倍率；三个位置标记、返回位置、选中部队集合；资源档位、资源最低值、选中/全图金矿金额；科技指定等级研究。
- 自动回血、回魔、清冷却绑定启用时所选最多32个己方单位，支持阈值、间隔、状态和一键停止。资源最低值共用调度器；全图金矿只枚举一次后分批处理。
- 可收藏常用功能并显式再次执行最近功能；执行记录保存最近10条结果。清理操作二次确认，只处理自身创建记录；不删已被持有的物品或扩展背包持有者。
- 不新增镜头设置、操作目标管理、单位信息页。位置、收藏和最近记录首先限定当前章节，不承诺跨章节迁移。目录和操作逻辑均内嵌地图。

精确数值和搜索通过每张地图独立的聊天前缀输入，提示会显示完整格式，60秒超时取消。关闭提示框保留待输入请求，返回主菜单取消。单位参数输入绑定原选择，执行时复核归属和存活状态，避免切换选择后改到另一单位。

目录使用私有内存gamecache分批初始化，避免经典JASS数组8192项限制；不调用SyncStored/SaveGameCache/Preload，不要求外部文件或插件。脚本归档附带`war3trainer/catalogue.json`及哈希，便于从最终文件重现完整payload。原JASS字节备份、可重复处理和归档校验继续沿用。

结果区分可读回状态和仅完成调用：经典接口没有通用冷却/无敌/朝向/缩放读回，不能将返回“已调用”冒充逐项效果验证。JASS预检与返回值判断不能捕获任意引擎崩溃或任意脚本线程中止。科技只升级，不以降级伪装撤销已触发的效果；位置返回也不撤销剧情事件。

- 激活：依次 ↑、↑、←、↓。
- 主菜单：激活后先 ↑ 再 Esc（1秒内）。
- 单位菜单：↑ 后双击单位。
- 帮助：`-h` 键盘；`-c` CMD；`-u` 单位类 CMD。

仅作以下兼容处理：

1. 移除标题校验触发的递归计时器，以及隐藏聊天接管逻辑。这两者不属于原版显示的正常功能。
2. 克隆标记使用脚本私有组，不占用地图的单位 UserData；保留中立玩家原名；游戏缓存使用本脚本独立名称。
3. 保护3.0背包控制能力及其自定义派生能力、载体物品及其派生物品。原版六格物品接口不暴露这些载体；拥有3.0背包的单位跳过旧式额外背包分页。原本的3.0专用功能继续处理扩展背包、装备与天赋。
4. 沿用已验证的保留原脚本字节、原子副本输出、内外MPQ属性与无关成员校验、重复处理和原脚本备份方案。

本版面向本地单人JASS地图与战役。原版使用经典 common.j 与 Blizzard.j，不调用重制版 Blz/Dz 扩展，也不需要桌面修改器保持连接。编译、归档和桌面验证不等于实际游戏中逐功能验收；多人同步、非样本自定义机制不能据此保证。
